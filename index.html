Why PanCode

What one agent
leaves open.

One agent on one model leaves questions open. Which model should take this task? What may a command touch? Did the check really pass after the last edit? What did yesterday’s session learn? Who runs the next ten tasks? PanCode is the harness that answers them, on the models you already use.

It does not replace your coding agents. Panos, PanCode’s orchestrator agent, delegates tasks to the ones you have installed, adopts their skills after you review them, and serves PanCode to ACP editors.

01 / Route

Any provider,
one set of tools.

Every provider has its own wire format, cache and price. PanCode drives each one on its own wire, and a 32K local model gets the same tools, rules and checks as a frontier API.

Use a model server on your own GPU, a lab gateway, a cloud API, or a subscription you already pay for. Chat and workers can use different models, and /model switches mid-session. Reasoning, vision, and diffusion models run through the same tools and rules.

Asks the server first
PanCode asks the live inference server what a model can do before it trusts a packaged profile. A context window nobody reported is shown as unknown.
Keeps the cache warm
The stable part of each prompt stays byte-identical and is split the way each provider’s cache expects, so repeated input is billed at the cached rate.
Explains a cache miss
When a provider reads less from cache than expected, PanCode records which part of the request changed.
Local and self-hosted
Ollama · LM Studio · llama.cpp · vLLM · SGLang · Lemonade
Gateways and institutions
LiteLLM · OpenAI- and Anthropic-compatible APIs · Argonne ALCF through Globus
Cloud and subscriptions
OpenAI · Anthropic · Google · OpenRouter · Groq · Mistral · DeepSeek · Inception · ChatGPT, Claude, and GitHub Copilot sign-in

02 / Remember

Long tasks that
remember.

A context window is storage, and it fills. What leaves it, and when, decides what a long task costs.

Panos is PanCode’s orchestrator agent, the one you talk to. Ask Panos to trace a calculation or explain how a project builds. It reads files, searches the tree, inspects Git history, and navigates a codemap, and a PANCODE.md handbook gives it standing project context.

Evicts before it summarizes
Old tool output moves out to exact records before any paid summary runs. A marker stays behind with the call that returns the output unchanged.
Prices each eviction
Removing early context forces the provider to rewrite its cache. PanCode weighs the tokens freed against that rewrite, so cleanup does not cost more than it saves.
Carries measured facts
When a summary runs, file hashes, the latest numeric results, and your request word for word travel with it.
Remembers across sessions
Requirements, failed attempts and diagnoses stay in session memory. A note tied to a command that succeeded becomes a lesson once other sessions demonstrate it or you approve it with pancode memory.

“Explain how this repository builds and runs its tests. Find the main entry points. Do not change files yet.”

03 / Delegate

Delegate bounded tasks
to a graded fleet.

A group of agents is a workload. Each job needs a route, a share of a real endpoint, and a way to tell whether it did its work.

Hand a side task to a worker while your conversation continues. Workers can be PanCode’s own, on any model you connected, or the coding agents you already use: Claude Code, Codex, OpenCode, Pi, and the Antigravity CLI.

Admits against capacity
Each run takes a slot on its endpoint, so a single-slot local server is not oversubscribed.
Grades the return
Each role owes specific evidence. A worker that comes back without it is retried once on another model.
Reviews on citations
A reviewer must cite what it read, and a verdict that cites nothing does not pass.
Lands the work
A playbook runs a sequence of workers, and pancode fleet land lands the branches a run kept.

A / “Trace how the input file reaches the solver. Report paths and line numbers. Do not edit files.”

B / /run verifier Review the current diff and run the relevant existing checks. Do not edit files.

04 / Contain

Contain every command,
at any autonomy.

A command is a process you did not write. It runs with your permissions unless something stands in the way.

By default, shell commands run inside an OS sandbox when the host has one, and PanCode snapshots your files before it changes them. A command the sandbox contains, or one a snapshot can undo, runs without an approval card.

Sandbox
A sandboxed command writes only to the workspace and scratch space. It cannot see your credential stores, the SSH agent, other agents’ logins, shell histories, or a project’s .env files.
Safety judge
A judge reviews the calls that would otherwise wait for you. It reads your own messages and the call itself, never the model’s reasoning or tool results.
A floor in yolo
Yolo removes approval cards. Hard blocks on protected paths, snapshots, and the rule that only you change project trust all stay.
Undo
/rewind previews and restores your files from a snapshot. It never moves your branches or index.
Steering
During a turn, Enter queues a message for the next pause between tool calls, Alt+S sends it now, and Escape interrupts.
Information flow
A project can declare which files may reach which model connections. It stays off until you approve a policy.

05 / Verify

Verify “done”
against what ran.

A finished task is a claim. PanCode checks it against what it observed.

Ask Panos to run declared tests, builds, and numerical comparisons. Results are recorded with their exit status, and a quality policy can map changed paths to required checks.

Claimed and assessed
The agent states done, partly done, or not done, and PanCode records its own assessment beside it. A “done” that left unvalidated changes is recorded as partly done.
Only the final tree counts
An edit after the last passing check reopens the claim.
Numbers, within a tolerance
A check can compare results within a relative, absolute, or ULP tolerance, repeat a seeded run, or reproduce from inputs pinned by hash.
A sealed record
Every run seals its journals, and pancode telemetry verify rechecks them on any machine.
Unknown stays unknown
Usage and cost keep measured, estimated, and unknown apart. An amount nothing measured never reads as zero.

06 / Interfaces

In the terminal
or on the desktop.

Start a task in either one. Both run the same PanCode runtime and share your saved connections and settings. The terminal is the primary interface, and a second terminal in the same folder opens its own session. The desktop app is served from your own machine, opens in your browser, and is in alpha.

Conversation, tool calls, permission cards, worker activity, and context accounting in one keyboard-driven workspace. /config opens your connections without leaving the session, and /resume followed by a session id reopens earlier work. Launch it from your repository.

For scripts and CI, pancode run --output-format json does one task with no screen and prints one versioned result: the answer, the exit code, and a typed cause for it. Flags bound requests, tool calls, cost, and time, and --dry-run previews the run without calling a model.

pancode

Keep many tasks open in one window. A new launch focuses it under WSL, as an installed Chrome or Edge app, or on Linux desktops with a window tool; otherwise it opens a browser tab. The Session column shows live usage, the plan, Git state, and artifacts. Idle tasks pause and resume on request. The alpha covers a subset of terminal workflows.

pancode gui --open

07 / PanHub and PanKit

Automation, memory,
and integrations.

01

Continuity

Name a session and resume it by name, fork a conversation with /fork, schedule turns with /loop, and prepare a reviewed handoff when a session runs long.

↗ 02

PanHub packs

Install plugins, skills, agents, prompts, playbooks and extensions with pancode hub or /hub, each pinned by the SHA-256 of its whole tree, or author your own. A plugin carries content. An extension is code that declares what it may do, and it loads only after you approve those capabilities. Packages that come with a project load only after you approve them for that workspace.

↗ 03

Editors and other agents

Use PanCode from ACP editors, and bring Claude Code and Codex hooks, MCP servers, and instructions with pancode interop adopt.

↗ 04

PanKit servers

PanCode ships MCP servers for node facts, software modules, Spack, Darshan I/O traces, scientific data, dataset catalogs and the project store. pankit serves them to any MCP host, and you can hand any MCP server’s tools to workers under explicit trust.

↗ 05

Pipelines

An extension can add interview steps, hooks, and tools, and pin what the model must keep in view. A prompt template can run one step per turn, cap each turn's budget, and carry a body per model tier. pancode run --answers runs the pipeline headless from an answers file.

↗ 06

Scripts and CI

One versioned JSON result, typed exit codes, run limits, a dry run, and answers validated against your JSON Schema. pancode schema run-result prints the contract.

↗ 07

Memory from evidence

A note is a claim tied to a command that succeeded or a file that was read. It becomes a lesson after other sessions demonstrate it or you approve it, and it is rechecked before it reaches the model.

↗ 08

Project store

Keep results and datasets outside the working tree. Each file carries who put it, from where, and its hash, and every checkout and task worktree sees the same store.

↗

Opt-in: System One and diffusion models stay off until you choose them, remote workers run only on nodes you add, and the files and music docks stay off until you enable them. Read how each subsystem is designed and measured.

08 / Install

Install PanCode
and connect a model.

You need a model with tool calling. Linux, macOS, and WSL are the primary platforms. The installer downloads one verified bundle that carries its own Node.js, needs no root, and works on HPC login nodes. On Linux it offers to add the desktop app at the end.

Installation & update guide →Install on a cluster →
1 / Install

Native install Recommended

macOS, Linux, WSL

$curl -fsSL https://pancode.dev/install.sh | sh

Downloads one verified bundle that carries its own Node.js, needs no root, works on x64 Linux with glibc as old as 2.17, and installs the latest release. On macOS, commands run under a sandbox-exec profile not yet verified on a real Mac. On Linux, add sh -s -- --gui after the pipe to set up the desktop app without being asked.

Windows PowerShell

Native Windows is best effort, so use the current stable release. An optional release job boots the package on Windows and runs only --version and --help. No automated check covers the install itself, which has been run by hand on one x64 machine with PowerShell 5.1, so WSL remains the recommended route on Windows.

PS>irm https://pancode.dev/install.ps1 | iex

npm

$npm install -g @akougkas/pancode

Needs Node.js 22.19 or newer. Update with pancode upgrade.

bun

$bun add -g @akougkas/pancode

Still runs on Node.js 22.19 or newer from your PATH. Update with bun, then run pancode upgrade --post-install.

Then open a new terminal and run pancode --version. Quickstart and troubleshooting →

If the shell cannot find pancode, add the PATH line the installer printed to your shell profile, or install again with sh -s -- --modify-path after the pipe.

2 / Connect a model
cd /path/to/your/project
pancode configure

Its first choice, Guided setup, offers any model connection it finds on this machine, or asks what you have: an API key, a subscription, a model server or gateway, or a setup file from your lab or team. It sends the model one short test request and saves when it answers. The desktop app offers the same setup. Already connected? Skip to step 3.

09 / Questions

Common questions.

Do I need a PanCode account?

No. PanCode runs locally with your own model connections. Your cloud provider may require credentials and charge for inference.

Is PanCode free?

PanCode is source-available under the PanCode License 1.0. It is free for individuals, small organizations, and noncommercial research and teaching. Larger organizations need a commercial license from the author, Anthony Kougkas.

Can I use a local model?

Yes. Connect a supported server or compatible API endpoint. Choose a model that supports tool calling. The connection guide covers setup.

What can PanCode change on my machine?

PanCode can edit files and run commands. At default autonomy, your session’s bash and run_script calls and dispatched native workers run in an OS sandbox when available (bubblewrap on Linux, an unverified sandbox-exec profile on macOS). yolo keeps that sandbox by default. Without a sandbox backend, or at unconfined yolo, commands run with your user’s access. Review permissions and changes as you work.

Are experimental features on by default?

No. System One and music stay off until you turn them on, and remote workers run only on nodes you add and test. Each tutorial on one of these says what enables the feature, which version it describes, and where your data goes.

Does it update itself?

Installer installs update in the background, at most once a day. On Linux and macOS, npm, pnpm, bun, and volta installs you own update after an interactive session quits. Set interface.autoUpdate: false to keep the notice and update by hand with pancode upgrade.

What does it record, and where does that go?

Every session and worker run writes journals under PanCode’s local state directory. Nothing reaches the maintainer until you send it: /report shows the masked draft first, and a diagnostic bundle stays on your machine because report sharing is turned off in this build. Your prompts and code go to the model endpoints you connect.

How is it different from Claude Code, Codex, or OpenCode?

Those are coding agents, and PanCode works beside them. Panos can delegate a task to each of them, pancode interop adopt brings their skills and prompts in after review, and pancode acp serves PanCode to ACP editors. PanCode adds the harness around the work: routing across providers, sandboxed commands, verification, memory and fleets of workers.

Four questions are worth asking of any coding agent. Can a script read the result? pancode run --output-format json prints an outcome and typed causes such as verify_failed. Will it say when the work is not finished? run --exit-code exits 1 when the agent declared partly done or PanCode lowered a “done” that left unvalidated changes.

Can you check a run later? pancode evidence inspect shows what a worker ran and verified, and pancode telemetry verify rechecks the sealed record on another machine. Does it check numbers? A quality policy can require a comparison within a tolerance or a reproduction from pinned inputs.

What changes when I upgrade?

PanCode is pre-1.0, so commands and settings can change between minor releases. pancode upgrade installs the new version, and the changelog lists what changed in each release.

How mature is the project?

PanCode is pre-1.0 software under active development. The terminal is the primary interface; the desktop is an optional alpha. Report an issue if you run into trouble.

Who builds it

Built by one maintainer.

Anthony Kougkas develops and maintains PanCode, a harness for the models and coding agents you already use, used on HPC and scientific software. It is pre-1.0, and the source and issues live on GitHub.
