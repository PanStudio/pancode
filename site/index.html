What PanCode is

A harness for coding work,
in three steps.

PanCode runs in your terminal, with a desktop app in alpha. It works beside the coding agents you already use and replaces none of them.

  1. Step 1

    Install

    One command installs a verified bundle that carries its own Node.js. It needs no root and no account.

    Install commands →
  2. Step 2

    Connect a model or an agent you already use

    pancode configure finds the model connections on this machine, or takes an API key, a subscription, a model server such as Ollama or vLLM, or a setup file from your lab. Claude Code, Codex, OpenCode, Pi and the Antigravity CLI join as workers.

    Connect a model →
  3. Step 3

    Give it work

    Describe the task in the terminal or the desktop app. PanCode routes it, runs commands inside the limits you set, and checks the result against what ran.

    Your first session →

Around any agent, five things are decided. PanCode holds them:

  1. 1 / RouteWhich model gets the work
  2. 2 / VerifyWhether “done” is true
  3. 3 / ContainWhat a command may touch
  4. 4 / DelegateWho else takes part of the job
  5. 5 / RememberWhat survives the session

1 / Route

Use every model and agent
you already have.

PanCode connects a model server on your own GPU, a lab gateway, a cloud API or a subscription you already pay for. /model changes the model mid-session, and chat and workers can run on different models. A 32K local model gets the same tools, rules and checks as a frontier API.

Choose a model for your project →How the drivers work →

2 / Verify

“Done” is a claim,
checked against what ran.

Declared tests, builds and numerical comparisons run through verify and are recorded with their exit status. An edit after the last passing check reopens the claim. In a script, pancode run --verify "npm test" --fail-on-verify exits 1 when the check fails.

Check a change against your repository →How accounting works →

3 / Contain

Let it work,
inside limits you set.

Shell commands run in an OS sandbox when the host has one, and files are snapshotted before they change. /rewind restores them. Hard blocks on protected paths stay, even in yolo. External agents and workers on fleet nodes run outside PanCode’s sandbox.

Containment and /rewind →How protection works →

4 / Delegate

Hand bounded tasks
to a graded fleet.

PanCode hands bounded tasks to workers: its own on any model you connected, or Claude Code, Codex, OpenCode, Pi and the Antigravity CLI. Each run takes a slot on its endpoint, and each role owes specific evidence. A worker that returns without it can be retried once on another model. pancode fleet land lands the branches a run kept.

Coordinate your coding agents →How scheduling works →

5 / Remember

Long tasks
keep what matters.

A context window fills. PanCode moves old tool output out to exact records before any paid summary runs, and a summary carries file hashes, the latest numeric results and your request word for word. A note tied to a command that succeeded becomes a lesson once other sessions demonstrate it or you approve it.

Install

Install PanCode
and connect a model.

You need a model with tool calling. Linux, macOS and WSL are the primary platforms.

macOS, Linux and WSL

$curl -fsSL https://pancode.dev/install.sh | sh

One verified bundle with its own Node.js, no root, x64 Linux with glibc as old as 2.17. On Linux it offers the desktop app at the end. The macOS sandbox-exec profile is not yet verified on a real Mac. Open a new terminal afterwards so pancode is on your PATH.

Windows PowerShell

PS>irm https://pancode.dev/install.ps1 | iex

Native Windows is best effort and has no sandbox. The install has been run by hand on one x64 machine, so WSL remains the recommended route.

npm or bun

$npm install -g @akougkas/pancode
$bun add -g @akougkas/pancode

Needs Node.js 22.19 or newer on your PATH. An npm install updates with pancode upgrade. After a bun update, run pancode upgrade --post-install.

  1. Connect a model
    $pancode configure
  2. Start the terminal
    $pancode
  3. Or the desktop app · alpha
    $pancode gui --open

Questions

Common questions.

Does PanCode replace my coding agent?

No. PanCode works beside it. Panos can hand a bounded task to Claude Code, Codex, OpenCode, Pi or the Antigravity CLI, and pancode interop adopt brings an agent’s skills and prompts in after you review them. External agents run outside PanCode’s sandbox.

Do I need a PanCode account?

No. PanCode runs locally with your own model connections. Your cloud provider may require credentials and charge for inference.

Can I use a local model?

Yes. Connect a supported server or compatible API endpoint. Choose a model that supports tool calling. The connection guide covers setup.

What can PanCode change on my machine?

PanCode can edit files and run commands. At default autonomy, your session’s bash and run_script calls and dispatched native workers run in an OS sandbox when available (bubblewrap on Linux, an unverified sandbox-exec profile on macOS). yolo keeps that sandbox by default. Without a sandbox backend, or at unconfined yolo, commands run with your user’s access. Review permissions and changes as you work.

Does it update itself?

Installer installs update in the background, at most once a day. On Linux and macOS, npm, pnpm, bun, and volta installs you own update after an interactive session quits. Set interface.autoUpdate: false to keep the notice and update by hand with pancode upgrade.

What is not finished?

PanCode is pre-1.0, so commands and settings can change between minor releases. The desktop app is in alpha. The macOS sandbox profile is not yet verified on a real Mac, and native Windows has no sandbox. On the research pages, every first experiment is proposed and not yet run.
