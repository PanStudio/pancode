See what a session cost and what a run did

PanCode records what each process, session, and worker run did in local journals, and every usage figure in every interface comes from those journals. This guide shows how to read a session's cost, find out why it stopped, check a run's record, and prepare an archive for the maintainers.

Version scope

Costs are shown with their provenance: a measured figure, an estimate, and an unknown value stay separate. An unknown stays unknown rather than becoming zero.

Before you start

  • PanCode installed, and at least one finished session in a repository.
  • The session id, which the exit summary prints. /resume also lists them.

Read the cost and the record

  1. 01

    Read it in the session

    /usage
/context
/usage health

    /usage covers session usage and supported subscription quotas. /context shows context use and the newest call's cache evidence. /usage health shows process health and route state.

  2. 02

    Read it from the shell

    Shell

    pancode telemetry inspect <session>
pancode telemetry cost <session> --by model
pancode telemetry calls <session> --limit 20
pancode telemetry cache <session>

    Each takes --json and returns the same data the terminal, editors, and desktop app read. For a repository over time, use pancode telemetry cost --repo . --days 30 --by model.

  3. 03

    Ask why it stopped

    Shell

    pancode telemetry why-stopped <session>
pancode telemetry timeline <session>
pancode telemetry explain <ref>

    explain shows how a figure was derived. --run <run-id> points inspect and cost at one worker run instead of a session.

  4. 04

    Check a record

    Shell

    pancode telemetry verify <session>
pancode telemetry verify --run <run-id>

    A sealed scope directory is self-contained, so you can copy it and verify it on another machine. verify checks journal segments, objects, and seals.

  5. 05

    Share it deliberately

    Shell

    pancode telemetry share --session <id> --profile content-free --dry-run
pancode telemetry share --session <id> --profile content-free --out report.tar.gz

    Without --send, share writes an archive and uploads nothing. content-free is the default profile, with structural records and no objects or content. structural adds objects that hold structure, such as prompt manifests. Read the dry run before you send anything.

What you should see

Figures labelled by provenance, and a verify result that names any gap. A clean verify shows the journals are internally consistent. The chain is unsigned, so it does not show who wrote them, and it says nothing about whether the work was correct.

Control what is kept

telemetry.mode defaults to standard, which keeps accountability and operational records without prompt content. research mode, telemetry.research.content: true, and pancode telemetry consent for the workspace are all required before prompts and request bodies are kept. Consent is stored in your own state directory, keyed by the workspace's real path, so a file committed to a repository cannot grant it.

pancode telemetry prune is a dry run unless you pass --apply.

Boundaries

  • Figures depend on what the provider reports. Calls with unknown usage are counted separately.
  • Quota rows are what a provider account reports, shared across sessions, and are separate from session spend.
  • pancode usage report is experimental.
